Common `aosp-17` / `7c9eb73` replaces XiaomiParts feature folders and entry points with Kotlin/Compose. Host owner fixtures pass HBM recovery, Alioth/India defaults and legacy dispatch, manual/preset/global/invalid-input/HAL-retry states, and all 26 regional profile-detail formatters. Four migration contracts check manifest entry points, resources, retired UI dependencies and exact regional policy data. Translations are untouched. Review required accessible row-switch and slider semantics; both were corrected.

The checkout Kotlin/Compose compiler and resource linker pass against existing platform dependencies; R8 dex conversion passes with the checkout compiler’s API-37 support warning. A signed APK was assembled for testing. A normal replacement install is rejected because XiaomiParts is persistent; a differently named package is also barred from joining the system UID. The temporary test package therefore omitted that UID and disabled boot receivers/services. It rendered display, global polling, speaker, MiSound, refresh, thermal and reference screens. System-profile expansion, touch help and all 13 Global profile-detail pages were exercised. Detail navigation caught a literal-percent formatting crash; the helper was fixed and the 13-page retest had no fatal log in its process. Host coverage also checks India details. The temporary package was uninstalled; the production package was not replaced.

These checks establish compile/resource/dex and rendered navigation behavior, including unavailable-hardware fallback. They do not establish privileged hardware writes, MiSound effect acceptance, speaker acoustics, boot restoration or full ROM installation. Backend fixtures simulate Android/HAL boundaries; root launching does not change the test package’s UID/SELinux domain.

Build constraint failure: the initial Siso dry run estimated 18 app actions, but actual `m XiaomiParts` expanded into about 5,990 actions and completed 2,128 before failing on an app resource attribute. Dependencies included framework resources. It stopped; no cleanup/output deletion, core source edits, alternate output configuration or further graph build was performed. The theme attribute was fixed; subsequent compile/dex/APK verification reused dependencies with temporary artifacts.
