# IQ-8275 firmware and source comparison

Observation date: 2026-10-28. **Downloaded, source-checked and host-tested**;
not deployed to Alioth. This record does not reopen Turnip or the declined OnePlus
experiment, and does not authorize a donor firmware installation.

## Material obtained

Using Qualcomm's [prebuilt image guide](https://dragonwingdocs.qualcomm.com/Key-Documents/Flash-Guide/obtain-prebuilts),
downloaded all four IQ-8275 QLI 2.1.1 images: normal and SOTA distributions, each in
open-source and proprietary variants. Total archives: 6,240,198,586 bytes. All four
passed complete ZIP CRC validation and have locally calculated SHA-256 inventories.
No independent publisher signature verification is claimed for these system ZIPs.
All four ext4 rootfs images were extracted without mounting or executing their code.
Normal-image userspace libraries were exported read-only; selected SOTA firmware
was extracted from the actual OSTree deployment paths.

Also obtained 131 related Markdown documentation pages, the graphics component
archive, board CDT, both release-recipe boot packages and the linked Ubuntu boot
firmware archive. Graphics and both recipe boot packages match their published
recipe SHA-256 values. Original licenses/notices remain with the private files.
Canonical's published Ubuntu desktop/server directories and release-notes PDF
returned HTTP 403 through both browser and CLI; those full Ubuntu images are not
in the collection. No access bypass or new license acceptance was attempted.

Private collection: `~/evo/.repo/research/iq8275-20261028`, with a README, final
inventories, origins/hashes and extracted binaries. Raw proprietary code, firmware,
authenticated page captures and account identifiers are not published here.

## Source identity and firmware findings

The [QLI 2.1.1 recipes](https://github.com/qualcomm-linux/meta-qcom/tree/b094cfccc192d8e02809bf87c6dd9c76bcf31330)
select [KGSL](https://github.com/qualcomm-linux/kgsl/commit/f374d957ba30cd3107f1ab007712e7f27b07def9)
and [Linux 6.18.44](https://github.com/qualcomm-linux/kernel/commit/8d0ad3756ce7d4febc2a5cbdc4d7ab9781d798ca).
Their checked-out versions match the pinned source revisions. The IQ machine
configuration intentionally shares QCS8300 boot-firmware packaging; the QCS8300
name in those official URLs is not a mistaken Alioth dependency.

Qualcomm's [graphics overview](https://dragonwingdocs.qualcomm.com/Technologies/Graphics/graphics-overview)
lists IQ-8275's shared `a650_sqe.fw` alongside its own `a623_gmu.bin` and `a623_zap`.
The checked KGSL source defines A623 and also retains A650 declarations using that
same SQE filename. It does not make GMU, ZAP, kernel or userspace interchangeable.

| SQE origin | Bytes | Version word |
| --- | ---: | --- |
| Alioth installed-source/stock dump | 31632 | `016dd093` |
| All four downloaded QLI images | 31964 | `016dd112` |
| Standalone graphics 1.877.3 archive | 31988 | `016dd114` |

The image version differs from the archive-bundled firmware. The inspected graphics
recipe installs userspace libraries but does not copy that bundled firmware
directory. All 17 compared regular graphics-library files match between the
proprietary system image and the standalone graphics package. These are glibc,
Wayland and GBM libraries; their ELF dependencies are not Android Bionic/HWC.
A display-named audio library was identified by its dependencies rather than
misclassified as a missing panel-color service.

## Offline checks and limits

A separate native QRISC disassembler was built from the retained Mesa 26.2.5 source
with all graphics drivers disabled. Alioth SQE and both downloaded SQE versions
disassemble successfully without stderr errors; private instruction comparisons
show changed contents rather than just renamed firmware. No Mesa driver was built
or deployed in this task. Decoding does not prove firmware compatibility, security,
GPU performance or correctness under Android's legacy KGSL stack.

No downloaded board binary was executed or flashed, and no Alioth production
prebuilt was replaced. The collection supplies reproducible comparison material;
it has not established a safe fix for Alioth's manual 60/120 color mismatch.
[Display evidence](displayfeature-evaluation-20261028.md) owns that investigation.

## Selected source integration

The later authorized [KGSL backport task](kgsl-backports-20261028.md) applies
compatible Qualcomm source fixes to Alioth, with build/host/device evidence.
The downloaded board binaries remain offline reference material. FastRPC,
AudioReach/PAL, Iris3 and newer wireless drivers have different platform/API
dependencies; no drop-in update was established for those Alioth components.
