# Alioth haptics rework — 2026-11-01

## Stock reverse engineering

Sources: `~/miui/out` (V816.0.5.0.TKHMIXM). The stock
`vendor.xiaomi.hardware.vibratorfeature.service` (SHA-256 `9cbc970e…409d`)
has a `.gnu_debugdata` symbol table, decompiled with Ghidra.

- `perform`: effect table built from `/vendor/firmware/*_RTP.bin` names
  `<id>_<name>_[<n>KHz_][S|P_][<gain>_]RTP.bin`. `P` means RAM via input FF
  with RAM ID = Android Effect ID. `S` or no flag means 24 kHz PCM through
  `custom_wave`. Magnitude is `16384*s+16383`; the default strength table is
  0/0.5/1.0, overridden per effect by `configStrengthForEffect` and a global
  `setAmplitudeExt` multiplier.
- `compose`, `getSupportedPrimitives` and `getPrimitiveDuration` are one
  unsupported stub. Stock A13 had no composition.
- `VibratorExt::play(int[])` is Xiaomi's dynamic-effect engine
  (`sys.haptic.dynamiceffect=true`). It mixes `SineTrack` (frequency
  `100+100*sharpness` Hz), `prebaked_Track` (10 embedded transients chosen by
  `sharpness*9`) and `HedTrack` (RichTap HE through `libaachaptics`). Only the
  MIUI framework calls it.
- An embedded 100–200 Hz drive-compensation table has its minimum (1.0) at
  166 Hz and about 8× at ±25 Hz. Stock clamps it to 1, so it only documents
  the narrow band. The device's cached f0 was 178.7 Hz.
- `miui-framework` `HapticFeedbackUtil`/`VibrateUtils`: each UI event uses
  `sys.haptic.<key>=RAM,code`; code 0/1/2 sends 0.375/0.625/1.0. Examples:
  VIRTUAL_KEY down `5,2`, LONG_PRESS `0,1`, KEYBOARD_TAP `3,2`,
  CLOCK_TICK mesh.light `5,1`. Most taps are full strength. The previous HAL
  treated those codes as the Android intensity levels.

## HyperOS .bin library

`/vendor/firmware` holds 274 `*_RTP.bin` (158 numbered copies in
`vibrator_firmware_aidl`, 116 identical named copies for the HIDL service) and
23 lowercase legacy UI files. All are headerless signed 8-bit 24 kHz PCM.

| IDs | Content |
| --- | --- |
| 0–20 | Zero-byte RAM markers (Android effects, ringtones 1–4 → RAM 6–9) |
| 23–59, 99, 154–156, 521 | Haptic tracks for MIUI ringtones, up to about 40 s |
| 60–99 | Notification/system tracks (charging, NFC, uninstall, screenshot…) |
| 72–93, 157–172 | UI: back gesture, up-slide, unlock failed, FOD, feedback ± |
| 101–153 | Game Turbo (PUBG/CFM) |
| 192 | Haptics video |

Android 17 sends only Effect enums 0–21. Ringtone tracks would need matching
MIUI ringtone audio and `config_ringtoneEffectUris`. UI, game and RichTap
content needs a framework or vendor-effect caller. No `.he` assets ship; RichTap
HE comes from apps through the MIUI extension, which A17 does not call.

- HAL `hardware_xiaomi` 0512a2f: HyperOS palette and base strengths, LIGHT ×0.6

## Verification and limits

`m android.hardware.vibrator-service.xiaomi_aw8697` passed. A later
comment-only edit was not rebuilt. The synthesizer passed a host ASan/UBSan
check: nonempty, bounded output, and fallback to 170 Hz for invalid f0.

On the phone (Enforcing, Magisk root for deployment only), the HAL and
vibrator directory were bind-mounted from tmpfs in the init namespace, then
the framework was soft-restarted. `dumpsys` then listed SPIN 59, QUICK_RISE 76,
SLOW_RISE 306, QUICK_FALL 66 and LOW_TICK 12 ms. Results:

- 7 effects × 3 settings and all 8 primitives finished once with no HAL errors.
- SLOW_RISE×3 took 986 ms; the MSDL SPIN×3 pattern took 344 ms (about 18 ms
  setup per step).
- DOUBLE_CLICK from the stock file took 138 ms. The FIFO returned idle.

The shell runs used COMMUNICATION_REQUEST usage, so touch-intensity strength
differences were not exercised on the device. The shell cancel did not target
those vibrations, so cancellation was not retested; that code is unchanged.

The test mounts stay active until reboot. No ROM build, flash, acceleration
measurement or human feel acceptance was done. AIDL v3 PWLE was not added
because it needs a measured G map.

## Tuning after maintainer feedback

The first palette felt weaker and unlike HyperOS: CLICK was weak, and sliders,
QS and the new effects felt bad. HyperOS UI feedback does not use RichTap. The
RichTap-compatible `DynamicEffect` API (HE JSON) only serves app SDKs, Game
Turbo and the Settings haptic-video demo, and the UI ships no HE assets.

A resonator fitted to the stock table (Q 18, f0 178.7) explains the result:
RAM 5 reaches 0.31 of RAM 0's output. The synthesized envelopes reached 2.3–5.3×
and rang for 50–66 ms, and stock LOW_TICK rang for 70 ms. Fix (`hardware_xiaomi`
e4e57aa, alioth `f8b5b6d`/`a1d9cec`):

- CLICK uses HyperOS `88_launcherIconSelection` (0.83, braked).
- TICK and TEXTURE_TICK use a 0.8 base and POP 1.0.
- Envelope levels are 0.2–0.25.
- Active damping is appended to every primitive; modelled ring-out is ≤0 ms
  (the model's motion settles before or as the tail ends).

The rebuilt HAL (`fc026b25…`) was mounted temporarily: 7 effects, 8 primitives
and SPIN×3 finished once with no HAL errors. Feel acceptance is pending. The
model has no measured acceleration.
