with the ROM. Standalone PBRP is a separate project and is not the source or
acceptance target for these changes. [Sources](../state/repositories.yaml),

## Existing-key storage and installation

`system/vold/recovery/RecoveryStorage.cpp` reuses Android 17 metadata encryption,
DE keys, synthetic-password derivation and CE-key installation. The verified
baseline handles user 0, no lock credential, SP v2/v3 and fscrypt v2 on Alioth's
legacy 4.19 kernel. It does not create replacement keys or format storage.

`/data` is mounted read-only. Keystore and locksettings databases, including
SQLite WAL, are copied into private RAM directories; original databases and key
files remain untouched. Recovery must not set `sys.boot_completed`, which would
permit irreversible Keystore hardware-key garbage collection. Helpers have a
bounded timeout and parent-death handling. Cleanup stops Keystore, Keymaster and
QSEE services and clears the listener-ready property, including failure paths.

`ApplyFromStorage` prepares logical/snapshot mappings and crypto dependencies,
then releases firmware, persist, ODM and vendor mounts before browsing or ZIP
installation. Installed filesystem keys remain available without the HALs.
Readonly bind-mounted storage uses the existing FUSE package installer. ZIPs are
whole-file signature checked; an unverified package requires explicit confirmation.
The completed full ROM OTA used secure production recovery's sideload path.

Raw-image installation is limited to validated physical boot-chain targets, with
explicit partition/slot/overwrite confirmation, capacity checks, fsync and
readback. Sparse, filesystem and logical-partition images belong in fastbootd.
The earlier raw-write diagnostic used a RAM-backed loop device, not a real boot
partition; do not transfer that result to every possible image/partition.

## Recovery dependencies and policy

Native recovery includes Keystore2, HIDL service management, Keymaster support,
filesystem tools and matching linker dependencies. Recovery-specific HIDL and
VINTF compatibility code does not replace normal Android HAL behavior.
The staged production root audit found 142 ELF files and no unresolved NEEDED
libraries. Packaging/VINTF/APEX-policy checks passed as part of the full build.

Keep policy recovery-only and preserve userdata/key-deletion neverallows. Crypto
and UI execution passed under enforcement in a diagnostic image whose init/adbd
were permissive. That is narrower than a fully secure end-to-end decryption test;
the full OTA itself and final Android boot used secure production recovery/ROM.
Final `ro.secure=1`, `ro.adb.secure=1`, `ro.debuggable=0`, SELinux Enforcing.

## Protected-credential work in progress

A temporary credential was configured after the verified baseline; its value
must never appear in public notes, commits, logs or process arguments. The current
candidate adds bounded scrypt, Gatekeeper verification, auth-token delivery to
Keystore, and masked PIN/password input using native recovery menus. Credential
material is bounded, RAM-only and wiped/unlinked on exit; verification does not
enroll, reenroll or delete Gatekeeper users and retains hardware retry delays.
Weaver, pattern and arbitrary Unicode input are not established by this candidate.

The broad `hal_client_domain` macro inherited passthrough Gatekeeper userdata
write permissions and failed recovery's neverallow. The correction grants only
binderized Gatekeeper client access; do not weaken the neverallow. HIDL recovery
variants are already generated by this tree; adding `recovery_available` to a
`hidl_interface` is unsupported and unnecessary.

Build and phone acceptance of the candidate are pending. Required checks: wrong
credential leaves CE storage locked; correct credential restores the same file
hash; all crypto services/dependency mounts are released; cancellation removes
RAM secrets; secure production recovery is restored. Do not call password support
verified until those checks pass.

## Source and build discipline

Preserve imported authorship and separate implementation, compatibility/policy
and translation topics. Approved published heads survived the 1,265-project
resync; 15 upstream projects advanced. [Manifest integration](../operations/framework-manifest.md)
tracks fork branches explicitly. Build/make overrides must preserve the six
upstream linkfiles and project groups, or a future sync loses `build/envsetup.sh`.

Current product remains `lineage_alioth-cp2a-user`. Use incremental builds for
implementation/fixes; reserve `m installclean` for final release preparation.
`repo sync -j50` is the requested sync parallelism, not a Soong job setting.
This full build used eight local jobs and two high-memory jobs without OOM.
The bundled Android 17 D8 reports an SDK-37 warning; do not substitute a random
compiler. The completed ROM boot/app smoke tests showed no crash/VerifyError,
but that is not proof of every dex/API path.

Older bundled-Magisk and PBRP observations belong to their historical source
candidates. Do not infer current native-recovery Magisk, root, MTP or password
acceptance from those records.
